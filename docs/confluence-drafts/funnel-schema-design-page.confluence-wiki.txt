h1. Funnel & User Journey Schema Design

h2. Overview

This document defines database schema for *saved funnels* and *user journeys* in Pulse.

*Funnel definitions* are stored in *MySQL* only. *ClickHouse* stores *pre-computed funnel results* written by *Spark* ({{otel.funnel_results}}). Raw product/custom events are *not* loaded into ClickHouse for the funnel pipeline — they remain in *S3* (Vector Parquet); Spark reads S3.

*Superseded:* The previous {{otel.product_events}} ClickHouse table design is *removed*. Do not create {{otel.product_events}} for funnel computation.

*Repo:* {{docs/architecture/funnel-mysql-clickhouse-schema.md}}, {{backend/ingestion/clickhouse-funnel-results-schema.sql}}

----

h2. MySQL — {{funnel}}

Stores saved funnel definitions (steps, filters, conversion window, mode). Spark and pulse-server load from here.

{code:sql}
CREATE TABLE IF NOT EXISTS funnel (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    funnel_id VARCHAR(64) NOT NULL UNIQUE,
    project_id VARCHAR(64) NOT NULL,
    name VARCHAR(255) NOT NULL,
    description TEXT NULL,
    steps JSON NOT NULL,
    window_seconds BIGINT NOT NULL DEFAULT 86400,
    mode VARCHAR(32) NOT NULL DEFAULT 'UNIQUE_USERS',
    ordered TINYINT(1) NOT NULL DEFAULT 1,
    closed TINYINT(1) NOT NULL DEFAULT 1,
    date_range_days INT NOT NULL DEFAULT 7,
    filters JSON NULL,
    tags JSON NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by VARCHAR(255) NULL,
    updated_by VARCHAR(255) NULL,
    is_archived TINYINT(1) NOT NULL DEFAULT 0,
    CONSTRAINT fk_funnel_project FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE,
    INDEX idx_funnel_project (project_id),
    INDEX idx_funnel_project_active (project_id, is_archived),
    INDEX idx_funnel_updated (updated_at)
);
{code}

*Implemented subset (repo):* {{V9__create_funnel_and_funnel_job_tables.sql}} uses {{steps_json}}, {{filters_json}} — align with this full schema in follow-up migrations.

h2. MySQL — {{journey}}

User journey definitions (anchor, direction, depth, thresholds, filters, tags).

{code:sql}
CREATE TABLE IF NOT EXISTS journey (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    journey_id VARCHAR(64) NOT NULL UNIQUE,
    project_id VARCHAR(64) NOT NULL,
    name VARCHAR(255) NOT NULL,
    description TEXT NULL,
    anchor_event_name VARCHAR(255) NOT NULL,
    anchor_type VARCHAR(32) NOT NULL,
    anchor_filters JSON NULL,
    direction VARCHAR(16) NOT NULL DEFAULT 'FORWARD',
    depth INT NOT NULL DEFAULT 5,
    date_range_days INT NOT NULL DEFAULT 7,
    thresholds JSON NOT NULL,
    filters JSON NULL,
    tags JSON NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by VARCHAR(255) NULL,
    updated_by VARCHAR(255) NULL,
    is_archived TINYINT(1) NOT NULL DEFAULT 0,
    CONSTRAINT fk_journey_project FOREIGN KEY (project_id) REFERENCES projects(project_id) ON DELETE CASCADE,
    INDEX idx_journey_project (project_id),
    INDEX idx_journey_project_active (project_id, is_archived),
    INDEX idx_journey_updated (updated_at)
);
{code}

h2. ClickHouse — {{otel.funnel_results}} (pre-computed only)

*Only* ClickHouse table for *funnel output* in this architecture. Spark writes after reading S3 Parquet. pulse-server reads for dashboard ({{GET /v1/funnel/<funnelId>/results}}).

{code:sql}
CREATE TABLE IF NOT EXISTS otel.funnel_results (
    funnel_id String,
    project_id String,
    run_date Date,
    step_index UInt8,
    step_name String,
    user_count UInt64,
    conversion_pct Float64,
    created_at DateTime64(3) DEFAULT now64(3),
    CONSTRAINT chk_step_index CHECK step_index < 32
) ENGINE = MergeTree()
PARTITION BY toYYYYMM(run_date)
ORDER BY (funnel_id, run_date, step_index)
SETTINGS index_granularity = 8192;
{code}

||Column||Description||
|funnel_id|Matches MySQL funnel_id|
|project_id|Project scope|
|run_date|Report date|
|step_index|0-based step|
|step_name|Event name|
|user_count|Users/sessions at step|
|conversion_pct|% from step 0|

----

h2. JSON shapes (summary)

* *steps:* array of objects with stepType, eventName, stepFilters (array)
* *filters / anchor_filters:* objects with field, operator, value (array) — e.g. Platform, GeoCountry, NetworkCarrier, OsVersion, AppVersion
* *tags:* string array
* *journey thresholds:* minUserPercentage, minAbsoluteUsers, maxPathsToShow, collapseRepeated

----

h2. Data flow

||Component||Role||
|MySQL {{funnel}}, {{journey}}|Definitions|
|S3 Parquet|Raw events (Vector)|
|Spark|Reads MySQL + S3 → computes → writes {{funnel_results}}|
|ClickHouse {{funnel_results}}|Pre-computed metrics only|

----

h2. StepType / PulseType mapping (explore / OTEL)

For *ad-hoc* analysis on OTEL tables (not Spark path): SCREEN → traces screen_load; INTERACTION → interaction; EVENT → logs/traces as today. Custom-event saved funnels use *S3 Parquet* schema (event_name, user_id, session_id, timestamp, filter columns).
