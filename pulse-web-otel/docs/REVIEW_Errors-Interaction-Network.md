## Interactions

> Scope: **Interaction sequences** (`pulse.type = interaction` OTLP spans, `src/interactions/`). Analysed against `docs/instrumentations/interactions/SPEC.md` and Android SDK (`instrumentation/interaction/`, `instrumentation/view-click/`, `instrumentation/click-common/`).

### How Android vs web work today


| Layer            | Android                                                                                                                                                                                             | Web (`pulse-web-otel`)                                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Config**       | Remote interaction definitions via `InteractionManager`                                                                                                                                             | `InteractionConfigFetcher` → `GET /v1/interaction-configs/` (dev) or prod JSON URL; `localStorage` cache; 30‑min refresh                                      |
| **Event intake** | `InteractionLogListener` (`LogRecordProcessor`): every **string-body** log → `addEvent(body)`; listed `eventName` / `pulse.type` values → `addMarkerEvent` + stamp `pulse.interaction.*` on the log | **Only** `Pulse.trackEvent(name, …)` → `InteractionFeature.trackEvent` → coordinator fan-out. `clicks.ts` / `navigation.ts` do **not** call the coordinator   |
| **Matching**     | `InteractionEventsTracker` + sequence matcher (parity)                                                                                                                                              | Same pipeline: `InteractionTracker` → `matchInteractionSequence` → `buildPulseInteraction`                                                                    |
| **Emit**         | Span with attrs + `span.addEvent` for **both** step events and marker events                                                                                                                        | Span attrs + `span.addEvent` for **local step events only** — `MARKER_EVENTS` stored in props but **not** added to span (bug)                                 |
| **Correlation**  | `InteractionAttributesSpanAppender` stamps `pulse.interaction.ids` / `names` on concurrent **spans and logs**                                                                                       | No span processor; coordinator state unused for correlation                                                                                                   |
| **Industry**     | N/A (Pulse-specific remote flows)                                                                                                                                                                   | **Sentry:** auto UI transactions + breadcrumbs on active transaction. **PostHog:** autocapture clicks/pageviews; no Pulse-style named multi-step remote flows |


**E2E today:** `ecommerce-demo/e2e/m2-interactions.spec.ts` drives sequences via `**Pulse.trackEvent` in page** (`interaction-test-helpers.emitEvent`) — not real DOM clicks. **Next.js demo:** no interaction span assertions.
