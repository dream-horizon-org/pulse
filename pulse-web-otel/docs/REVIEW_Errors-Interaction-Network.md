**Columns**


| Column         | Meaning                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------- |

| **Kind**       | `Code` · `Spec` · `Test`                                                                      |

| **Detail**     | Why it matters, in plain English                                                              |
| **Expected**   | What should be true; SPEC ref + Android / tool comparison where relevant                      |

## Interactions

> Scope: **Interaction sequences** (`pulse.type = interaction` OTLP spans, `src/interactions/`). Analysed against `docs/instrumentations/interactions/SPEC.md` and Android SDK (`instrumentation/interaction/`, `instrumentation/view-click/`, `instrumentation/click-common/`).

### How Android vs web work today


| Layer            | Android                                                                                                                                                                                             | Web (`pulse-web-otel`)                                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Config**       | Remote interaction definitions via `InteractionManager`                                                                                                                                             | `InteractionConfigFetcher` → `GET /v1/interaction-configs/` (dev) or prod JSON URL; `localStorage` cache; 30‑min refresh                                      |
| **Event intake** | `InteractionLogListener` (`LogRecordProcessor`): every **string-body** log → `addEvent(body)`; listed `eventName` / `pulse.type` values → `addMarkerEvent` + stamp `pulse.interaction.`* on the log | **Only** `Pulse.trackEvent(name, …)` → `InteractionFeature.trackEvent` → coordinator fan-out. `clicks.ts` / `navigation.ts` do **not** call the coordinator   |
| **Matching**     | `InteractionEventsTracker` + sequence matcher (parity)                                                                                                                                              | Same pipeline: `InteractionTracker` → `matchInteractionSequence` → `buildPulseInteraction`                                                                    |
| **Emit**         | Span with attrs + `span.addEvent` for **both** step events and marker events                                                                                                                        | Span attrs + `span.addEvent` for **both** step events and marker events — `MARKER_EVENTS` second loop added to `InteractionSpanBuilder` (ISS-I02 fixed)       |
| **Correlation**  | `InteractionAttributesSpanAppender` stamps `pulse.interaction.ids` / `names` on concurrent **spans and logs**                                                                                       | `InteractionContextSpanProcessor` forward-stamps `pulse.interaction.names` / `pulse.interaction.ids` (`string[]`) on spans started during in-flight flows; reverse-feeds eligible span ends (`screen_load`, `screen_session`, `network.*`) into `trackEvent` to advance waiting flows (ISS-I04 fixed)  |
| **Industry**     | N/A (Pulse-specific remote flows)                                                                                                                                                                   | **Sentry:** auto UI transactions + breadcrumbs on active transaction. **PostHog:** autocapture clicks/pageviews; no Pulse-style named multi-step remote flows |


**E2E today:** `ecommerce-demo/e2e/m2-interactions.spec.ts` — `@click-bridge` (3 DOM click tests) + `@marker` (3 ISS-I02/I03 marker-event tests) + `@M2 interaction-context-span` (4 ISS-I04 tests). `nextjs-demo/e2e/nextjs-demo.spec.ts` — `@ISS-I12` (3 click-bridge tests) + `@M2 interactions marker events` (3 ISS-I02/I03 marker-event tests) + `@M2 interaction-context-span — Next.js` (4 ISS-I04 tests). All pass in chromium/firefox/webkit.
